# SpotifySorter — Design Context

This file is the canonical design DNA for SpotifySorter. All design skills (`impeccable`, `ui-ux-pro-max`, `animate`, `polish`, `typeset`, `layout`, `delight`, `critique`) MUST read this before generating UI work.

## Design Context

### Users

Single user — the project owner. Personal music-curation tool, not multi-tenant. Used during relaxed evenings and late-night sessions while sorting ~2,000 tracks across 40+ playlists into themed sub-genre / mood playlists.

The user has specific musical taste (aesthetic rap, pop rap, sad slow songs as examples) and a strong opinion on visual design — explicitly rejected "AI slop" and asked for design plugins to be used throughout. They prefer point/click over CLI, but are technical enough to run a local Next.js dev server.

Context of use: sitting with headphones on, evening, choosing what to keep and what to organize. Not a quick task — a _deliberate_ one. The user wants to _enjoy_ this process.

### Brand Personality

Three words: **tactile, nocturnal, unhurried.**

Voice:

- Treats music with reverence — never as content-to-scroll.
- Speaks like a music nerd, not a SaaS marketer. "12 tracks" not "12 items." "Aesthetic Rap" not "Genre 7."
- Specific where SaaS would be generic.
- Quiet by default, opinionated when it matters.
- No exclamation marks. No "Awesome!" No "Let's go!"

Emotional goals: focused, intimate, private. Sorting through a personal record collection by lamp-light at 1am — not managing a database.

### Aesthetic Direction

**"Private record-listening room at 1am."** A tactile, record-store aesthetic interpreted in warm-toned dark mode. Not generic dark mode (no blue-shifted slate, no neon, no glow effects). Closer to playing a vinyl in a wood-paneled study with a single warm lamp on.

**Theme**: Dark by default. Light mode optional, secondary.

**Color palette** (OKLCH, neutrals tinted toward brand hue):

- Base bg: `oklch(0.16 0.012 55)` — deep coffee-brown black
- Surface: `oklch(0.20 0.014 55)` — card surfaces
- Surface raised: `oklch(0.24 0.016 55)` — modals, popovers
- Border default: `oklch(0.30 0.018 55)` — subtle dividers
- Text primary: `oklch(0.95 0.014 70)` — warm cream
- Text secondary: `oklch(0.72 0.020 65)` — muted amber
- Text tertiary: `oklch(0.52 0.025 60)`
- Accent (the 10%): `oklch(0.74 0.14 55)` — brass/amber
- Success: `oklch(0.66 0.12 145)` — muted moss (NOT Spotify green)
- Danger: `oklch(0.62 0.20 25)` — rust
- Warning: `oklch(0.75 0.13 80)` — gold

**Typography pairing**:

- Display: **Editorial New** (Pangram Pangram, free) — magazine/editorial-leaning serif with character. Used for headings, category names on cards, the "Apply" success screen.
- Body: **PP Neue Montreal** (Pangram Pangram, free) — clean grotesk with subtle warmth. All paragraph text, labels, buttons.
- Mono: **Geist Mono** (Vercel, free) — for track IDs, BPM-style technical data, code blocks in error details.

None of these are in `impeccable`'s reflex-reject list. None are Inter / DM / Plus Jakarta / Space / IBM Plex / Crimson / Fraunces / Playfair etc.

**Layout principles**:

- Asymmetric layouts. Strong typographic hierarchy. Generous whitespace.
- Track lists feel printed (like LP liner notes), with index numbers, generous gap, and a quiet "why" tooltip on hover.
- 60-30-10 visual weight (dominant warm dark surface / muted secondary / brass accent).
- 4pt spacing scale with semantic tokens (`--space-sm`, `--space-md` etc.), NOT pixel-named.

**Motion language** (Framer Motion):

- Default spring: `{ stiffness: 200, damping: 30, mass: 0.8 }` — natural weight, deceleration not bounce.
- Page transitions: cubic-bezier `[0.16, 1, 0.3, 1]` (exponential ease-out), 600ms.
- Stagger reveals on list-of-cards screens: `staggerChildren: 0.04, delayChildren: 0.1`.
- Drag interactions have weight — items don't snap to cursor instantly, they follow with slight delay.
- `useReducedMotion()` respected everywhere; reduced motion = instant transitions, no springs.
- NO bounce/elastic easing. NO endlessly-pulsing loaders. NO neon glow effects.

**Component aesthetic**:

- Buttons: text-driven, not box-driven. Primary = bold text with brass underline that animates on hover. Secondary = quiet text with amber transition. No rounded-rectangle button pills.
- Inputs: wide, generous padding, single bottom border (not boxed), focus state = brass underline.
- Cards: subtle 1px border tinted toward brand hue, NO rounded shadows. Hover reveals a quiet state change (border brightens slightly, NOT a glow).
- Lists: index-numbered, like LP track listings. Track titles in cream, artist names in amber-muted, optional "why" line in tertiary.
- Iconography: thin-stroke (1.25px) Lucide icons OR custom minimal SVG. Never large icons-with-rounded-backgrounds above headings.

### Design Principles

1. **Treat music with reverence.** Tracks aren't rows in a table — they're songs. Display them like liner notes (title, artist, the LLM's one-line "why" rationale on hover), never like spreadsheet entries. The track list IS the product; it deserves the most design attention.

2. **Earn every pixel.** Generous whitespace, but with intentional density where it matters. No decoration without function. No empty cards. No "Dashboard" headers above pages titled "Dashboard." No subtitle that repeats the title.

3. **Motion conveys state, not delight-for-delight's-sake.** When a category card splits on undo-merge, the motion shows you what happened. When the confidence slider drags, playlist track-counts re-flow with stagger. Framer Motion. Custom springs. `useReducedMotion()` honored.

4. **Print feel, not screen feel.** Type set like a magazine, not a UI. Mixed sizes for hierarchy, not mostly-the-same-with-bold. Spacing chosen like a print designer would (varied rhythm), not like a Tailwind starter.

5. **Quiet by default, loud only when it matters.** Status messages are quiet. Success states are quiet. Errors are quiet but clear. The one moment we let go: the **Apply success** screen, which displays your newly-created playlists with weight, type, and reverence — like the credits at the end of a record.

### Anti-references (explicit; design must NOT resemble any of these)

- ❌ **Spotify clone** (green-on-black) — the actual product we integrate with; looking like its sibling is forbidden.
- ❌ **Generic SaaS dark mode** — slate-900 cards, purple-to-blue gradients, neon cyan accents, glowing buttons. Exactly the AI-slop directive to avoid.
- ❌ **Linear / Notion / Vercel-aesthetic clones** — gray rounded cards in 12-col grid. Templated.
- ❌ **"Spotify Wrapped" infographic style** — loud gradients, hyper-saturated, gen-Z stickers, gradient text. Wrong tone.
- ❌ **"Futuristic" anything** — this entire genre is the AI default. Banned.
- ❌ **Side-stripe accent borders** on cards/list items (impeccable BAN 1).
- ❌ **Gradient text** (impeccable BAN 2).
- ❌ **Glassmorphism, glow effects, sparkline decorations.**
- ❌ **Pure black (`#000`) or pure white (`#fff`)** — always tinted.
- ❌ **Inter, DM Sans, Plus Jakarta Sans, Space Grotesk, IBM Plex, Cormorant, Playfair, Fraunces, Crimson** — all banned (impeccable reflex-reject list).

### Skills used during build

When generating any UI work for this project, the executing model MUST invoke (in approximate phase order):

- `impeccable` (craft mode) for each new screen
- `ui-ux-pro-max` for typography/palette/layout/component intelligence
- `animate` after baseline screen is built — choreograph Framer Motion
- `polish` for final pass on alignment, spacing, type details
- `critique` for evaluation before declaring any screen done
- `typeset`, `layout`, `delight` as needed for specific issues

`framer-motion` is the canonical motion library. No CSS keyframe animations beyond `<300ms` micro-transitions on hover/focus.
